## Challenges

### Recurring Race Conditions
Race conditions appeared in two stories without being caught pre-review:
- **3.2**: TOCTOU race — `count` check and `insert` are non-atomic; deferred to Story 7.2
- **3.4**: Double-click race — React state batching allows two concurrent RPC calls before the `deleting` guard re-renders; patched in review

Pattern: any guard-then-write Server Action and any async Client Component handler needs explicit concurrent execution review before code review, not during.

### Null Guards Missed Pre-Review
Story 3.2 had multiple null guard patches — `profile` after `.single()`, `configRow` after config query. These are defensive programming items that review correctly catches, but they appear systematically enough to warrant a pre-checklist.

### Story 3.2 Patch Count (12)
Story 3.2 was the first story combining authenticated Server Action + database write + tier gating + Client Component state management. The 12 patches seeded the defensive patterns that made 3.3 (1 patch) and 3.4 (4 patches) cleaner. The number reflects first-time complexity, not ongoing quality decline.

### Manual Verification Tracking Gap
Dev agents marked manual task checkboxes `[x]` before Jason confirmed them, while the change logs noted "pending Jason's sign-off." This created ambiguity about actual verification status. All manual tests were confirmed complete on 2026-04-26.

---

## Key Insights

1. **Race conditions are the recurring code review theme** — two epics in a row. A pre-review checklist for concurrent execution would catch these before review rather than during it.
2. **Story complexity spike in 3.2 normalizes quickly** — the patterns established in 3.2 reduced patch counts in subsequent stories. High patch counts on "first of kind" stories are expected and healthy.
3. **Manual verification needs explicit tracking** — task checkboxes are not sufficient; change logs must distinguish "pending Jason" from "verified by Jason."
4. **`AttentionRegion` is now built** — Story 4.1 extends an existing component (focus trap + Nano button tier), it does not create from scratch.
